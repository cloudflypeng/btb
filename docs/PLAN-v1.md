## 0. 定位：我们凭什么比官方好

官方客户端的问题主要不在功能，而在于：**广告与运营位多、启动重、首页信息噪音大、动效生硬且不可打断、iPad/Mac 体验敷衍、播放器手势与弹幕设置藏得深。**

BTB 的三条原则：

1. **内容即界面**：没有广告、开屏和运营弹窗，封面和视频本身就是主视觉，界面元素尽量退到后面。
2. **一切可打断**：所有转场都基于弹簧、跟手，可以在中途被抓住、反向或取消，不存在需要等它播完的动画。
3. **快于感知**：交互 100ms 内必有反馈，首帧画面 < 800ms；列表滚动在 120Hz 下不掉帧。

## 2. 功能点确认清单

优先级说明：**P0** 是 v1 必须完成的部分，**P1** 是强烈建议，**P2** 是加分项。工作量单位为人日，按 AI 辅助开发估算。

### A. 性能地基（P0，所有体验的前提）

- [x] **A1 性能基线与度量**：用 `os_signpost` 埋点（冷启动、首页首屏、点击到首帧、滑动掉帧率），配合 Instruments 模板和一个 `make perf` 脚本输出报告。**验收：每个 PR 能对比前后数据。**（1d）
- [x] **A2 图片管线重写**：用 ImageIO 按目标像素尺寸下采样（`kCGImageSourceThumbnailMaxPixelSize`），在后台解码；内存 LRU（按字节限额）+ 磁盘缓存（200MB 上限，可在设置中清理）；向 B 站图床请求 `@{w}w_{h}h.webp` 的尺寸后缀，按需取图。**验收：首页快速滑动 120Hz 掉帧 < 1%，内存峰值下降 40%+。**（2d）
- [x] **A3 列表预取**：滚动方向前方 2 屏的封面提前下载并解码；分页提前 3 个项目触发（沿用已有契约）。（0.5d）
- [x] **A4 拆分 AppModel**：按领域拆成 `FeedStore` / `PlayerStore` / `LibraryStore` / `MessageStore` / `AccountStore` / `SearchStore` 等，各自是独立的 `@Observable`；`AppModel` 只负责组装和路由。**验收：最大单文件 < 1000 行，页面之间不会互相触发刷新。**（3d，纯重构，行为不变）
- [x] **A5 冷启动优化**：首页 feed 落盘缓存，启动时先展示上次内容（stale-while-revalidate）；bbcore 初始化与 UI 并行。**验收：冷启动到可交互 < 400ms（iPhone 15 级别设备）。**（1d）

### B. 秒开播放（P0，核心竞争力）

- [x] **B1 预解析**：手指按下卡片（touch down / hover 300ms）时立即发起 `player.resolve`，结果缓存 60s。（1d）
- [x] **B2 首帧占位**：播放器先显示已缓存的封面作为首帧，视频首帧到达后交叉淡入，过程中不出现黑屏。（0.5d）
- [x] **B3 起播策略**：先用低码率快速起播，随后无缝切换到目标清晰度（AVPlayer `preferredPeakBitRate` 爬升，或由 bbcore 生成多档 variant）。**验收：点击到首帧 P50 < 800ms，P90 < 1.5s。**（2d，需要 bbcore 配合）
- [x] **B4 续播与进度记忆**：本地记录每个视频的播放位置，卡片封面底部显示进度条，与云端历史合并。（1d）
- [x] **B5 后台播放 / 锁屏控制 / 灵动岛**：`MPNowPlayingInfoCenter` + 远程指令；iOS 支持纯音频后台播放。（1d）
- [x] **B6 画中画完善**：从列表上滑离开播放页时自动进入 PiP（iOS）；Mac 支持悬浮小窗。（1d）

### C. 动效与转场（P0，「丝滑」的主体）

- [x] **C1 卡片 → 播放器的英雄转场**：封面从卡片位置放大成为播放器，详情内容从下方随弹簧滑入；下拉播放器时它会缩回原卡片位置（iOS 18 `navigationTransition(.zoom)`，iOS 17 用自研 matched geometry 兜底）。**验收：转场全程可被手势打断和反向。**（3d）
- [x] **C2 统一动效 Token**：只保留 3 组弹簧：`snappy`（响应 0.3，阻尼 0.85）、`smooth`（0.45，1.0）、`bouncy`（0.5，0.7）。现有 easeOut 时长全部替换为这 3 组；开启「减弱动态效果」时降级为透明度变化。（0.5d）
- [x] **C3 按压反馈**：卡片按下缩放到 0.97，带高光，松手回弹；长按弹出预览菜单（iOS `contextMenu` preview：静音自动播放片段 + 稍后再看/分享/不感兴趣）。（1d）
- [x] **C4 触感反馈体系**：点赞、投币、收藏、切换分 P、拖动进度条到章节点、下拉刷新阈值等节点触发 `sensoryFeedback`；Mac 端使用触控板力反馈。（0.5d）
- [x] **C5 一键三连动画**：长按点赞触发环形进度，完成后三个图标依次弹出并散开粒子；结果乐观更新，失败时回滚。（1d）
- [x] **C6 列表入场与内容替换**：首屏卡片错峰淡入（间隔 30ms，只在首屏出现时播放）；数字变化用 `contentTransition(.numericText())`；Tab 切换时内容横向滑动并跟手。（1d）
- [x] **C7 骨架屏与真实内容共用布局**：骨架和最终卡片尺寸完全一致，加载完成时原位淡入，不产生布局跳动。（0.5d）
- [x] **C8 视频下方常驻操作栏**（用户建议，已完成第一版）：播放器正下方固定一行「点赞 / 投币 / 收藏 / 稍后看 / 缓存 / 分享」，不跟随下方内容滚动；图标在上、计数在下，激活态用品牌色，不用色块；计数变化带数字滚动；长按点赞出现环形进度，触发一键三连。Mac 端把操作栏和 UP 信息一起固定在播放器下方。（0.5d）

| 点击 → 首帧，长按（预热已就绪并并入） | **300 ms** |
| 点击 → 首帧，快速轻点 120ms × 5 次 | 537 / 553 / 604 / 741 / 1177 ms（P50≈604，P90≈1177） |
| 预解析（含 playurl） | 300–350 ms |
| 预解析 + 建流 | 540–970 ms |
| 播放器自建流（未命中预热） | 641 → 92 ms（并入命中时）；未命中时 210–420 ms |
| 首段内存缓存生效后单次复测 | `play.resolve 82ms` → `play.stream 253ms` → 首帧 **603ms**，播放正常推进（19s 内进度 13.7s / 1210s） |

补充：bbcore 里 `player.resolve` 与 `stream.start` 会各调一次 playurl，已加 45s 短期缓存（按 cid/清晰度/fnval/账号，忽略 bvid/aid），首个预热建流命中时 `play.stream` 直接 0ms。

iOS 模拟器同路径：tap → 首帧 621ms（流走网络）/ 426ms 级（解析并入）。

调试中发现并修复的三个坑（已写进代码注释）：
1. `NSKeyValueObservedChange.newValue` 在 `.initial` 回调里是 `nil`，必须读 `observed.status`；
2. 给视频层加 `opacity(0)` 会阻止 `AVPlayerLayer.isReadyForDisplay` 变真，首帧永远等超时——封面必须是叠在**可见**视频层之上的遮罩；
3. 重定向到 pipe 时 stdout 是全缓冲，`devicectl --console` 会吞掉尾部日志，调试打印需 `fflush`。
